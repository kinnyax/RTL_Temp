# ADC_TOP v0.4 RTL Handoff

## Outcome

ADC_TOP was refactored to the user-reviewed v0.4 contract. The implementation
keeps explicit fixed-eight hierarchy and a single AXI4-Stream per AFE, removes
the PCIe/DMA duplicate paths and `DATA_ROUTE`, and preserves JESD PHY/GTH as an
external later-integration boundary.

ADC_RXD's self-written 32-sample extension is explicit and contains no
`function/generate/genvar`. The consolidated ADI source remains unmodified
inside `rtl\ADI_JESD204`. ADC_REG now follows the SPI_REG-style Protocol,
Address Decode, and Register Encode/Readback organization. Hardware PD sets are
explicit; only its three whole-register W1C blocks use procedural `for`, with
clear before set so events win.

State machines use `pkt_fsm/pkt_fsm_nx` and
`tgc_fsm/tgc_fsm_nx`, state updates use `<= #UDLY`, and ordinary internal
DFF outputs use `_r`. The redundant ADC_RXD byte-aligned input and all old
route interfaces were removed. No local Git commit was created.

## Review Result

Final static review confirms:

- ADC_TOP/ADC_SYNC/CHN_SYNC contain no `always` blocks;
- self-written RTL contains no `function/generate/genvar`;
- procedural `for` occurs only in the three approved ADC_REG W1C blocks;
- every AFE exposes only `m_axis_afeN_*`;
- no `data_route`, PCIe/DMA stream, `.vlt`, or redundant ADC_RXD
  byte-aligned input remains;
- ADI provenance file/hash and read-only PUB dependency hashes remain intact.
