# ADC_TOP 用户 RTL 设计偏好草稿

## 状态与用途

- 状态：`DRAFT / USER_PREFERENCE_MEMORY`
- 记录日期：2026-08-18
- 当前用途：供 ADC_TOP 后续讨论、架构和 RTL 修改前读取。
- 非正式约束：本文件当前不是设计合同、RTL Schema、验收标准或已验证功能定义。
- 后续处理：用户确认 AC9810 重复数据问题并完成相关修改后，再由用户授权与 `rtl-vibe` 的 `rtl-schema` 合并。
- 优先级：当前用户指令、已确认的原始协议证据和最终设计合同高于本草稿。

## 总体目标

RTL 不仅要实现功能，还应让设计者能够直接从代码看出数据结构、配置公式、计数过程和状态变化。优先采用满足实际协议的最小结构，避免为了不可能出现的配置或过度通用性引入大量信号、分支和隐式坐标换算。

## 设计流程偏好

1. 先从原始数据手册、组帧表格或可信波形还原实际数据结构。
2. 将数据结构拆成同步字段、prefix、有效数据区、零区、块边界和异常条件。
3. 优先按实际结构选择少量状态和正向计数器，再设计数据缓存与 FIFO 写入。
4. 配置差异优先表示为清晰公式，不先建设通用查表或通用调度框架。
5. 软件保证合法静态配置时，不为非法配置堆叠复杂功能路径；保留必要的安全复位、运行时异常上报和软件恢复接口。
6. 在修改 RTL 前先确认公式含义、单位、计数起点、边界是否包含当前拍，以及表格是否存在笔误。

## 命名偏好

- 名字表达信号的真实用途，不使用容易误解为时序阶段或终点坐标的名字。
- 计数器使用 `*_cnt`，缓存使用 `*_buff`，组合窗口使用 `*_window`，切片使用 `*_slice`。
- 推荐示例：`block_cnt`、`phase_cnt`、`region_cnt`、`rxd_buff`。
- 配置公式可按来源拆分，例如 `pref_fra + pref_del = pref_num`。
- 模式专用公式应在名称上区分 single-decimation、DDC、prefix、有效区和零区语义。
- 保留用户已经调整过的信号名和排版，除非存在语义冲突、声明错误或用户同意统一修改。

## 公式表达偏好

- 优先正向加法计数，不使用倒计数或可能产生负数含义的表达。
- 模式和小数系数选择优先采用紧凑、分层清楚的三目运算。
- 复杂结果优先拆成若干有实际含义的部分，再相加得到最终结果。
- 公式名尽量短且能直接对应数据手册，例如以 `gap_64n_32` 表示公式 `64N-32`。
- 明确区分表格中的零区长度、块起点间隔、块头坐标和块尾坐标，避免同一个 `gap` 名承载不同含义。

## 状态机与时序块偏好

- 状态数量应尽量少，每个状态只负责一种清晰的数据阶段。
- 优先使用类似 `IDLE / PREF / PAYL` 的直接状态命名。
- 数据状态按照“找到同步位置、跳过 prefix、接收有效数据、跳过零区、拼包写 FIFO”的自然顺序组织。
- 时序 `always` 块按寄存器职责拆分；单个块只管理一个寄存器，或一组必须同沿更新且语义紧密相关的寄存器。
- 删除无必要的显式自保持赋值；复位、清除、更新和保持优先级必须直观。
- 状态寄存器、数据计数器、阶段计数器和接收缓存应尽量由不同的时序块管理。

## 数据路径偏好

- 优先直接接收数据、按有效区/零区计数、拼满固定宽度后写入 FIFO。
- 固定协议已经保证的对齐关系，不额外建设过度通用的历史窗口、偏移比较树或多路切片逻辑。
- 当每拍输入 128 bit、目标块为 256 bit 时，优先考虑两拍写入 `rxd_buff` 后完成一块。
- 只有原始协议确实存在拍内边界或跨拍拼接时，才保留逐 word mask、窗口或切片；必须在代码旁能追溯到对应协议证据。
- 异常数据不强求 RTL 自动恢复全部上下文；应可靠产生软件可见状态，由软件执行关闭模块、清 FIFO、重新配置和恢复。

## 当前待确认事项

- AC9810 “单开抽取”表格中 `N.5`、2CML 行重复出现的终端采样，用户判断为表格书写错误，真实链路不会重复发送。
- 该判断尚未形成正式设计输入，不能据此修改现行 RTL、设计合同或验证模型。
- 若确认不重复发送，需要重新冻结 `N.5` 的有效区/零区长度、块起点间隔和周期，并重新评估是否可以删除 `rxd_window` 与多偏移 `rxd_slice`。

## 后续与 rtl-schema 合并原则

- 只合并已经由用户确认、且至少在一个实际 RTL 修改中验证有效的偏好。
- 将通用编码规则与 ADC_TOP 专用协议规则分开；ADC 表格公式不得写成所有模块的通用 Schema。
- Schema 应检查可读性和职责边界，但不强制机械格式覆盖用户手工排版。
- 合并前逐项审查与现有 `rtl-vibe` 规则是否冲突，冲突项由用户选择，不静默覆盖。
